# 客服工单趋势与异常分析工具设计

## 1. 背景与目标

客服主管需要从大量工单中快速识别近期增长的问题、重复出现的根因和需要优先处理的异常。目前依赖人工翻看列表，效率低且容易遗漏跨工单信号。

本项目针对 2024-06-01 至 2024-06-11 的 50 条工单数据，构建一个可复现的 Python 分析工具。工具生成机器可读的结构化结果和可离线打开的 HTML Dashboard，帮助主管回答：

- 哪些类别或细分问题近期增多？
- 哪些未解决、高优先级或超长处理工单需要立即关注？
- 哪些问题持续损害满意度？
- 不同渠道在效率和体验上是否存在差异？

本工具只描述样本内变化，不将 11 天、50 条记录夸大为长期趋势，也不进行缺乏数据支撑的预测。

## 2. 范围

### 2.1 包含内容

- 将提供的工单 JSON 和字段说明纳入仓库。
- 校验数据结构、必填字段、时间、枚举和数值范围。
- 计算时间、类别、主题、优先级、解决状态、处理时长、满意度和渠道指标。
- 使用确定性规则发现趋势及异常，并保留判断证据。
- 生成结构化 JSON 与单文件离线 HTML Dashboard。
- 生成 Dashboard 截图，供 README 和提交材料使用。
- 提供自动化测试和简明 README。

### 2.2 不包含内容

- 数据库、后端服务、账号体系和在线部署。
- 实时数据接入、定时任务或告警推送。
- 在线大模型推理或不可复现的运行时 AI 分类。
- 长期预测、因果推断或正式 SLA 合规判断。

## 3. 技术方案

采用 Python、pandas 和 Plotly：

- pandas 负责清洗、派生字段、分组聚合和统计。
- Plotly 负责生成可交互图表，并将运行资源内嵌到 HTML。
- Python 标准库负责 JSON 序列化、模板组织和文件输出。
- pytest 验证数据加载、指标、异常规则和输出文件。

不引入 Web 框架。用户运行一条命令后得到可直接双击打开的报告，兼顾可复现性、展示效果和项目复杂度。

职责边界：

- `tests/`：只验证公开分析结果和输出契约，避免与内部实现过度耦合。

## 5. 数据流

1. 从 `data/tickets.json` 读取记录。
2. 按字段说明校验必填字段、类型和取值范围。
3. 解析创建时间，并派生日期、时间窗、低满意度、超长处理等字段。
4. 按确定性关键词规则将描述归并为细分主题。
5. 计算总体、趋势、类别、主题、严重程度、效率、体验和渠道指标。
6. 执行异常规则，记录等级、依据、指标值、关联工单和建议动作。
7. 将统一分析结果写入 `report/analysis_summary.json`。
8. 使用同一份结果生成 `report/dashboard.html`，避免页面数字与结构化结果不一致。
9. 通过本地浏览器打开报告并生成 `report/dashboard.png`。

## 6. 分析维度

### 6.1 工单量与时间趋势

按日统计工单总量，比较前半窗口（6 月 1–5 日）和后半窗口（6 月 6–11 日）的类别日均量与占比。由于两个窗口天数不同，增长判断使用日均量而不是原始总数。

决策价值：判断近期工作压力是否变化，以及增长由哪些业务问题驱动。

### 6.2 问题类型与文本主题

在已有 `category` 分类之下，根据描述中的明确词语归并细分主题，包括但不限于：

- 重复或错误扣款
- 支付成功但订单异常
- 支付页面或结算失败
- 退款审核或到账延迟
- 退货运费报销
- 物流停滞或异常
- 客服机器人无效回复

未命中规则的记录归为“其他”，并保留原始描述和类别，不强行分类。

决策价值：类别用于资源配置，细分主题用于定位可执行的产品或流程根因。

### 6.3 严重程度与风险积压

交叉分析优先级、解决状态、处理时长和满意度，重点列出高优先级未解决、中优先级未解决及复合风险工单。

决策价值：形成主管可以直接跟进的优先清单。

### 6.4 服务效率

按总体、类别和渠道计算平均处理时长、中位数和 P90。中位数描述常态，P90 揭示长尾，平均值用于与常见管理报表对齐。

决策价值：识别处理瓶颈和拖累整体效率的长尾问题。

### 6.5 客户体验

统计满意度均值、分布和低分率，其中 1–2 分定义为低满意度。分析其与类别、渠道、解决状态和处理时长的关系。

决策价值：确认哪些问题和流程最伤害客户体验。

### 6.6 渠道差异

比较在线和电话渠道的工单结构、解决率、中位处理时长和低分率。邮件渠道在本数据中没有样本，只作为字段允许值记录，不生成虚假比较。

决策价值：判断渠道分流、升级或人员承接机制是否需要调整。

### 6.7 关联风险

观察处理时长与满意度、未解决与低满意度、类别与高优先级之间的组合关系。相关展示用于发现共现，不宣称因果。

决策价值：发现单一指标无法揭示的系统性风险。

## 7. 异常检测

每条异常包含唯一标识、标题、风险等级、规则说明、实际数值、基准值、关联工单 ID 和建议动作。

### 7.1 类别激增

满足以下全部条件时触发：

- 后半窗口的日均工单量比前半窗口增长至少 50%；
- 后半窗口至少包含 5 条该类别工单。

报告同时展示两个窗口的天数、数量、日均量和增长率。

### 7.2 重复主题聚集

同一细分主题出现至少 2 次时作为重复信号。若满足任一条件则提高风险等级：

- 至少一条记录未解决；
- 至少一条记录满意度不高于 2；
- 至少两条集中在样本最后 3 个自然日。

### 7.3 高风险积压

- 高优先级且未解决：立即处理。
- 中优先级且未解决：持续关注。
- 低优先级且未解决：信息提示。

### 7.4 处理时长异常

处理时长至少 48 小时，或超过所属类别 P90 时触发。48 小时是本分析采用的观察阈值，不代表企业正式 SLA。

### 7.5 体验异常

满足任一条件时触发：

- 某类别至少 3 条工单，且低分率至少 50%；
- 单条工单未解决且满意度不高于 2。

### 7.6 渠道异常

仅当参与比较的渠道各自至少有 5 条样本时判断。比较解决率、低分率和中位处理时长；Dashboard 展示差值和样本量，由主管结合业务背景判断，不对小样本做强结论。

### 7.7 复合风险排序

复合风险分仅用于排序，不替代原始证据：

- 未解决：+4
- 高优先级：+3；中优先级：+1
- 满意度 1–2 分：+2
- 处理时长至少 48 小时：+2

同分时依次按未解决、高优先级、处理时长和创建时间排序。Dashboard 始终展示构成风险分的原始字段。

## 8. Dashboard 设计

页面采用管理看板式浅色主题，按纵向阅读顺序组织：

1. **数据概览**：样本日期、总工单数、未解决数、高优先级数、平均满意度、处理时长中位数。
2. **主管今日应关注**：按“立即处理、持续关注、信息提示”展示异常卡片，包含证据、关联工单和建议动作。
3. **趋势变化**：每日工单趋势，以及前后窗口类别日均量对比。
4. **问题结构**：类别分布、细分主题排行、优先级与解决状态。
5. **服务效率**：处理时长分布、类别效率和渠道对比。
6. **客户体验**：满意度分布、类别低分率、处理时长与满意度散点关系。
7. **方法与限制**：规则阈值、样本限制、生成时间和数据口径。

风险使用红、橙、蓝区分，同时提供图标或文字标签，确保不依赖颜色传达信息。图表有标题、数值、样本量和简短结论。页面在常见桌面宽度下适合截图，并在窄屏上按单列排列。

## 9. 错误处理

- 文件不存在、JSON 解析失败或顶层结构不是数组时，输出明确错误并以非零状态退出。
- 缺少必填字段时，错误包含工单位置和字段名。
- 无法解析时间、非法枚举、负处理时长、满意度超出 1–5 时拒绝生成报告。
- 空数据集输出明确提示，不生成误导性指标。
- 某分组样本不足时保留样本量并跳过强结论。
- 报告输出目录不存在时自动创建。

## 10. 测试与验收

### 10.1 自动化测试

- 50 条记录能够完整加载，工单 ID 唯一。
- 日期、布尔值、枚举、满意度和处理时长校验正确。
- 总量、解决状态、优先级、满意度和处理时长汇总正确。
- 不等长时间窗按日均量进行比较。
- 主题关键词归并具有稳定输出。
- 异常阈值边界正确，例如 49% 不触发、50% 触发。
- 复合风险评分及同分排序正确。
- 结构化 JSON 和 HTML 均能生成，且包含必要字段与页面区块。

### 10.2 人工验收

- 执行 README 中的一条命令后生成报告。
- `dashboard.html` 无需服务即可打开，图表和交互正常。
- 页面关键数字与 `analysis_summary.json` 及原始数据一致。
- 异常卡片均能追溯到具体规则和工单。
- 生成完整 Dashboard 截图，并在 README 中展示。
- README 包含分析维度、关键趋势与异常、运行方式、项目结构、AI 使用情况和数据限制。

## 11. AI 使用说明

README 将如实说明：

- 使用 Cursor AI 协助梳理需求、设计分析维度、编写与检查代码、组织报告表达。
- 运行时的数据清洗、指标计算、主题归并和异常检测均采用仓库中可见的确定性代码。
- 不将工单内容发送给外部在线模型，报告可以离线复现。
- 所有关键发现均由原始字段和明确规则支持，AI 不作为最终判断依据。
